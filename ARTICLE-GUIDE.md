# Как собирается Артикул (Norkpalm ↔ Планфикс)

Этот документ — про формат одной позиции заказа (`product-schema.json`, `product-reference.json`)
и формулу, по которой Планфикс собирает Артикул из её полей. PlanPlace присылает свой артикул
вместе с заказом, а Планфикс пересчитывает Артикул заново, динамически, из тех же полей по тем
же правилам — совпадение и есть проверка, что данные дошли корректно.

Формат самого вебхука (запрос/ответ) описан отдельно — см. `request-schema.json` и
`response-schema.json`.

## 1. Изделие решает, что ещё нужно заполнить

Каждая строка заказа начинается с выбора **Изделия** (например, «Фасад GLIX», «Полка
LUMIX», «Профиль ESTET» — полный список в `product-reference.json → productDirectory`).

У каждого Изделия в справочнике есть свой набор флагов «что обязательно»:
- нужен ли **Тип профиля**,
- нужен ли **Параметр**,
- нужен ли **Вариант**,
- нужна ли **Вставка**,
- нужно ли обязательное **Примечание**.

Это единственный источник истины: если для конкретного Изделия поле не отмечено как
обязательное — передавать его не нужно (и это будет ошибкой валидации, а не просто
лишним пустым значением). Если отмечено — без него заказ не пройдёт.

Отдельно у каждого Изделия есть привязанный **Профиль** (даёт код для 1-го сегмента
артикула) и **Тип изделия** (определяет два дополнительных правила: возможна ли Сборка,
и не должна ли Ширина быть строго равна 0).

## 2. Обязательные поля

Независимо от того, что за Изделие выбрано, всегда обязательны:

| Поле | Тип значения |
|---|---|
| Стандарт | Да / Нет |
| Сборка | Да / Нет |
| Цвет | выбор из справочника (код) |
| Длина | число, мм |
| Ширина¹ | число, мм |
| Количество | целое число, шт. |

¹ кроме изделий, где у Типа изделия отмечено «ширина не требуется» — тогда должно быть
строго 0, не пусто.

**Примечание** становится обязательным отдельно в двух случаях: если это требует само
изделие (см. §1), **или** если Стандарт = «Нет».

## 3. Формула артикула

Артикул — не конкатенация всех полей подряд, у него три части:

```
[СЕГМЕНТ-1] - [СЕГМЕНТ-2] - [ЦВЕТ.ДЛИНА[.ШИРИНА]]
```

Правая часть простая: код цвета, точка, длина, и если ширина не ноль — ещё точка и ширина
(дробные значения — с запятой, не округляются: `482.5` → `482,5`).

Тип профиля, Параметр и Вариант — три разных поля, но **в какой сегмент попадёт значение,
решает не само поле, а конкретная выбранная запись справочника**: у каждой из них отдельно
прописана «Область артикула» — 1 (сегмент-1) или 2 (сегмент-2). Два значения одного и того
же поля вполне могут оказаться в **разных** сегментах. Область указана прямо в
`product-reference.json` при каждой записи (`profileTypeDirectory[].articleArea`,
аналогично для `parameterDirectory` и `variantDirectory`).

Есть и третий вариант — область **3**: такие значения существуют в справочнике и видны
в интерфейсе, но **в артикул не попадают вообще**. На практике это редкий частный случай:
встречается только у трёх значений Тип профиля («45», «100», «200» — все три под изделия
MIXBOX). У Параметра и Варианта область 3 не встречается ни разу — там всегда 1 или 2.

**Как собираются сегменты:**
- **СЕГМЕНТ-1** = код Профиля изделия + (через точку) коды всех выбранных
  Тип-профиля/Параметр/Вариант с областью = 1, в порядке Тип → Параметр → Вариант.
- **СЕГМЕНТ-2** = коды всех выбранных Тип-профиля/Параметр/Вариант с областью = 2,
  тем же порядком, склеенные точками между собой (без ведущей точки).

Живой пример на реальных данных — одно и то же изделие «Фасад LACONIC», меняется только
выбор в поле Тип профиля:

```
Тип профиля = «Прямой» (код M, область 1), Параметр = H2 (область 2), Вариант = 10/2A (область 2)
   → Артикул = LC.M-H2.10/2A-RAL.2400.600

Тип профиля = «Высокий … (слева и справа)» (код AC, область 2), Параметр = H2 (область 2), Вариант = 10/2A (область 2)
   → Артикул = LC-AC.H2.10/2A-RAL.2400.600
```

Код профиля LC (LACONIC) остаётся на месте — Тип профиля перескакивает из Сегмента-1 в
Сегмент-2 только из-за того, какая именно запись выбрана. Это не баг и не
непоследовательность — так задумано в самой формуле Планфикса, и наша сборка артикула
это воспроизводит один в один.

## 4. Спецкейс: GLIX + «0 пет.»

Если Профиль изделия содержит подстроку **GLIX** и выбранный Параметр = **«0 пет.»** —
Вариант перестаёт быть обязательным, даже если для этого Изделия Вариант в целом отмечен
как обязательный. Это единственное встроенное в саму формулу исключение из общего правила
гейтинга — жёстко прописано в Планфиксе именно под этот профиль, не выводится из общих
правил.

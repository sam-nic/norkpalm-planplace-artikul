Передача заказа: PlanPlace → Планфикс

Формат вебхука, которым PlanPlace передаёт заказ в Планфикс, и формат ответа, который Планфикс возвращает обратно. Формат самой позиции заказа и формула Артикула — отдельным документом, см. «Как собирается Артикул».

§1

Запрос

Заказ передаётся одним вебхуком — JSON-объектом с двумя полями: contact (кто разместил заказ) и items — массив изделий, ровно по одному объекту на строку заказа.

ПолеОбязательноНазначение
contact.firstNameдаИмя контактного лица, разместившего заказ.
contact.lastNameдаФамилия контактного лица.
contact.emailдаEmail — по нему заказчик идентифицируется в Планфиксе.
itemsдаМассив позиций заказа — формат одной позиции см. в «Как собирается Артикул».

Пример (полностью в приложенном request-example.json):

{
  "contact": {
    "firstName": "Иван",
    "lastName": "Иванов",
    "email": "ivanov@example.com"
  },
  "items": [
    {
      "product": "Фасад GLIX",
      "profileType": "Левый",
      "parameter": "2 пет.",
      "variant": "Стандартная",
      "insert": "Артиста",
      "insertTreatment": [],
      "standard": "Да",
      "assembly": "Нет",
      "color": "RAL",
      "length": 2400,
      "width": 600,
      "quantity": 2,
      "note": null
    }
  ]
}
§2

Ответ

На вебхук Планфикс отвечает синхронно — статусом обработки, id созданного объекта заказа и, опционально, прямой ссылкой на этот заказ в личном кабинете дилера. Детализации причины ошибки нет — на стороне Планфикса пока нет её разбивки по кодам/причинам, поэтому status сообщает только сам факт «ок» или «не ок».

ПолеОбязательноНазначение
statusда"ok" или "error".
taskIdда, если okId созданного в Планфиксе объекта заказа.
dealerCabinetUrlнетСсылка на заказ в ЛК дилера — может отсутствовать даже при status = "ok".

Пример успешного ответа (полностью в приложенном response-example.json):

{
  "status": "ok",
  "taskId": 508783,
  "dealerCabinetUrl": "https://norkpalm.example/cabinet/orders/508783"
}
